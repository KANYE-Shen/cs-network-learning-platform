## 3. 新图代理甲：10个独立图

只创建 src/components/figures/refresh/ch1 和 refresh/ch3-control 下的新模块；每图独立组件，可共享同目录真实实体部件。输出默认组件及 proposed figureId / subsectionId / anchor knowledgeId / supported knowledgeIds / 模型说明给整合代理。

1. s1.1.2 k1.1.4：协议规则与顺序，用两台有状态操作终端和握手锁扣，展示请求/应答顺序与错误顺序。
2. s1.2.2 k1.2.5–9：接入网，用家庭接线/分配设备实体台，模式区分DSL专线段、HFC共享段、无线接入，不能暗示全程独享。
3. s1.2.3 k1.2.10–11：介质，用可辨认的双绞线/同轴/光纤剖面与无线天线对照，选介质对应信号和性质；传播速度不等于吞吐。
4. s1.3.2 k1.3.5–6：转发/路由/数据报与虚电路，用带查表拨片的分拣机构，分清建立规则与逐包执行，路径模式不能混同。
5. s1.3.3 k1.3.7：ISP层次，用真实机柜/交换节点/端口跳接台，演示接入ISP、上游、对等连接；层级是模型，不画绝对树。
6. s1.4.1 k1.4.1：吞吐量，用三段容量闸口和流量读数，吞吐取瓶颈与共享约束，输入改变需反映在动画和数值。
7. s1.4.3 k1.4.6：丢包，用有限缓冲与队满尾丢分拣台，展示到达/处理速率和缓冲容量改变如何影响丢包；区分排队丢包与比特差错。
8. s1.5.1 k1.5.1–3：分层服务，用可拆解的分层设备接口装配台，区分服务接口与对等协议；三种层模型切换需正确。
9. s3.5.2 k3.5.4：RTT/超时，用往返探测与可调计时器台，RTT样本、估计与超时边界一致，不把超时画成固定RTT倍数定律。
10. s3.5.5 k3.5.9–11：连接管理，用双端锁闩与独立方向状态灯，模式展示两次失败、三次握手、四次释放；保留序号/ACK及TIME_WAIT教学条件。

只创建 src/components/figures/refresh/ch2 和 refresh/ch3-reliability 下的新模块，其他边界同甲。

2. s2.1.3 k2.1.5–6：传输服务需求，用服务能力选择仪，可靠/时延/吞吐需求与TCP/UDP提供能力准确匹配，UDP本身不保证低时延。
3. s2.2.2 k2.2.5–6：HTTP报文/状态码，用请求/响应检验台和字段抽屉，阶段显示报文类别/关键字段，不能把状态码当请求头。
4. s2.2.3 k2.2.7–9：Cookie/缓存/条件GET，用身份票据柜与资源缓存检验台，多模式展示状态关联、命中/未命中、条件验证；304无实体正文的逻辑正确。
5. s2.4.2 k2.4.4：取信协议，用邮箱存储柜与双终端，区分POP3下载策略、IMAP服务器同步，不武断声称POP3总删除邮件。
6. s2.5.1 k2.5.1–4：DNS服务/组织，用目录卡柜与分级权威服务节点，域名→资源记录而非URL→网页，分布式组织与权威边界准确。
7. s2.6.1 k2.6.1：文件分发，用源站和对等分发机械台，按正文公式模型展示客户端服务器与P2P的下界，不能把理论下界当任意拓扑实测耗时。
8. s3.4.1 k3.4.1–4：可靠传输演进，用检错/确认/序号/计时四个组件的验证台，正确区分rdt1/2/2.1/2.2/3的假设和新增机制。
9. s3.5.1 k3.5.1–3：TCP报文/Seq/ACK，用字节刻度卷尺与接收装配台，ACK为下一个期望字节，分清段计数与字节序号。
10. s3.5.3 k3.5.5–7：TCP可靠数据传输，用缓存/累计确认/重传触发机械台，区分快重传与超时，不把ACK丢失必然等同数据重传。
