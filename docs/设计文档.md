# 计算机网络交互式学习平台 · 设计文档

> 版本 v1.0 · 2026-10-22

## 1. 目标与定位

一个**可长期使用**的个人计算机网络学习平台。内容依据哈工大威海《计算机网络：自顶向下方法》课程 PPT（Chapter1-3，授课教师王凯教授），面向中文大学生与考研复习。

**核心承诺**：
1. **内容准确优先**——机制、公式、协议逻辑必须正确，PPT 中可能的笔误要标注纠正。
2. **数据安全**——内容持续更新时，学习记录（收藏、错题、首次与历史作答、进度）绝不丢失。
3. **真的能学**——不是 PPT 搬运，而是"为什么需要它 → 核心思路 → 内部机制 → 与类似机制的差别"的因果式讲解。
4. **真的能操作**——重点协议与算法有可交互的演示，不是装饰性动画。

## 2. 技术选型与理由

| 选型 | 理由 |
|---|---|
| **React 18 + TypeScript + Vite** | 生态成熟、构建快、类型安全保证内容数据结构一致 |
| **HashRouter** | 关键决策：产物是纯静态文件，用户可能放在任意目录甚至直接双击 `index.html` 打开。Hash 路由不需要服务器 rewrite 配置，避免"部署后刷新 404"的长期困扰 |
| **Tailwind CSS** | 统一设计语言（间距/圆角/阴影/配色），深浅主题通过 CSS 变量 + `dark` class 实现，避免维护两套样式 |
| **Dexie (IndexedDB)** | 用户数据量小但结构化、需要事务与索引查询。IndexedDB 是浏览器原生持久化，**刷新不丢失**；Dexie 提供类型化 API 与版本迁移钩子 |
| **KaTeX** | 公式渲染首选——比 MathJax 快得多，且无需联网加载字体 |
| **Zustand** | 仅用于少量全局 UI 状态（主题、侧栏），避免 Redux 的样板代码 |
| **vitest + fake-indexeddb** | 与 Vite 同源，测试快；`fake-indexeddb` 让持久化逻辑可在 Node 中被真实验证 |

**未引入**：后端服务、云同步、账户系统、MDX 编译链。
- 原因：本项目定位是"本地长期可用"，引入后端会大幅提高维护成本，与"可离线、可备份迁移"的目标冲突。
- 课程内容用 **TypeScript 数据模块**（而非 MDX）：本项目的内容是**结构化**的——每个知识点有 `insight`（四问）、`blocks`（富文本块数组）、`sources`（可追溯性）、`questionIds`/`demoIds`（交叉引用）。用 MDX 反而要把结构化数据塞进 JSX，得不偿失。

## 4. 内容数据模型

所有内容都是**纯数据**。核心类型见 `src/types/content.ts`。

### 4.1 知识点
```ts
{
  id: 'k1.3.2',              // 稳定 ID，永不改变
  title, en, summary, tags,
  sources: SourceRef[],     // 可追溯性：PPT 页码 / 补充 / 考研考点 / 外部链接
  insight: {                // 四问速览
    why, coreIdea, mechanism, comparison
  },
  blocks: ContentBlock[],   // 正文
  questionIds, demoIds, related
}
```

### 4.2 ContentBlock（正文块）
`p` / `h` / `list` / `callout`(note|why|warning|exam|tip) / `formula` / `vars` / `example` / `table` / `term` / `kv` / `quote` / `compareRef` / `demoRef` / `knowledgeRef` / `figure`

正文中的 `$...$` 与 `$$...$$` 由 `ContentRenderer` 统一交给 KaTeX 渲染。

### 4.3 题目
```ts
{
  id: 'q1.3.2-01',          // 稳定唯一 ID
  type: 'single'|'multiple'|'judge'|'numeric'|'short',
  chapterId, knowledgeId, tags, difficulty, source,
  sourceRef,               // 来源：PPT 原题 / 原创 / 王道
  stem: ContentBlock[],     // 提交前不得泄露答案
  options: [{ key, text, explain }],   // 每个选项都有独立解析
  answer: string[],
  analysis: ContentBlock[],
}
```

## 5. 用户数据模型（与内容完全解耦）

`src/db/studyDB.ts`，Dexie 表：

| 表 | 主键 | 用途 |
|---|---|---|
| `attempts` | `++id` | **全部**作答记录（含首次与重做），字段 `first` 标记是否首次 |
| `mistakes` | `questionId` | 错题本条目：`auto`(自动加入) / `manual` / `mastered` |
| `favorites` | `questionId` | 收藏 |
| `progress` | `knowledgeId` | 知识点学习进度 |
| `recent` | `id` | 最近学习位置（栈式，保留 30 条） |
| `settings` | `key` | 设置、schema 版本、错题移除墓碑 |

### 5.1 错题本规则（严格实现）
```
首次正式提交答错 → 自动加入错题本（auto=true）
首次正式提交答对 → 不加入
后续做错         → 保留作答记录，但不改变首次判定，不重复自动加入
手动加入/移除     → 支持；移除不删除 attempts
标记已掌握        → mastered=true，可随时取消
移除后重新加入    → 通过 settings 中的墓碑记录与"重新加入"按钮实现
```

### 5.2 备份与恢复
- **导出**：`exportBackup()` → 标准 JSON，含 `app` / `schemaVersion` / `exportedAt` / `contentVersionAtExport` / 全部数据表。
- **导入**：`importBackup(json, mode)`，`mode` 为 `merge`（默认，合并去重，同 ID 取较新）或 `replace`（覆盖，事务内完成，失败回滚）。
- **校验**：非法 JSON、来源不符、缺少字段、schema 版本高于当前应用 → 明确抛错，**绝不覆盖现有数据**。损坏记录被跳过并计入 `skippedCorrupt`。
- **无云同步**：界面明确说明数据只在本设备，需靠备份文件迁移。

## 6. 增量更新机制

### 6.1 ID 契约
`src/content/outline.ts` 是唯一真相来源。新增 PPT 时：
1. 在 `outline.ts` 中**追加**新的 section/subsection/knowledge ID（`k{ch}.{seq}`），旧 ID 一律不动。
2. 内容写入 `chapters/chX.ts`，题目 ID 沿用 `q{k-id}-NN` 规则。
3. 用户数据（IndexedDB）**不随内容重建**——因此旧收藏、错题、进度自然保持有效。

### 6.2 兼容性保障
- 内容 ID 稳定 → 题目/知识点 ID 稳定 → 用户记录的外键始终有效。
- 对**被删除**的知识点/题目：用户记录**不删除**（保护学习数据），仅在「数据备份 → 版本与完整性」中报告孤儿引用数量。
- `db.version(1)` 预留了 Dexie 的 schema 迁移机制；将来若要改表结构，在 `db.version(2).stores({...})` 中声明即可，IndexedDB 会自动迁移。

### 6.3 新增 PPT 的操作流程
见根目录 `新增PPT操作指南.md`。

## 7. 交互演示系统

25 个演示，分布在 `src/components/demos/`。统一通过 `DemoHost` 注册表（`component` 字段 → 懒加载组件）。

**统一交互规范**（`DemoKit.tsx`）：
- 播放 / 暂停 / 重置 / 单步 / 调速（0.5× ~ 4×）
- 关键参数可调（滑块、下拉、开关）
- 当前步骤高亮 + 同步文字解释（`StepNote`）
- 实时状态/变量展示（`ResultGrid`）
- 主题自适应（使用 CSS 变量），响应式布局

**协议逻辑准确性要求**（已在开发规范中作为硬性约束）：
- GBN 接收方丢弃乱序包、只发累积 ACK；超时后重传窗口内所有包。
- SR 接收方缓存乱序包并按序交付；只重传丢失的包；序号空间需 ≥ 2N。
- TCP 确认号是**期望收到的下一个字节序号**。
- TCP 三次握手/四次挥手状态迁移与 PPT 第 78-81 页一致。

## 9. 已知限制与内容缺口

见 `课程内容覆盖报告.md` 的"未实现与内容缺口"一节。核心限制：
- 仅覆盖 Chapter1-3（应用层、传输层、导论）。网络层（IP/路由）与链路层（以太网/CSMA）尚未讲授，站点暂不含该章内容，但对比表与知识框架中预留了衔接位置。
- 部分 PPT 幻灯片是纯图片/示意图，无法用文字完整表达，已在覆盖报告中逐页列出并说明替代方案（多数以 SVG 重绘的交互演示承载）。
- 真实互联网协议与课堂模型的差异（如 TCP 拥塞控制的四状态 FSM vs 实际 CUBIC/BBR）已在相关知识点中显式标注。
