## HTTP 报文语义检查

- 报文行使用完整 HTTP/1.1 起始行；请求头采用 `Host`、`Content-Type`、`Content-Length`、`Accept`、`Cache-Control` 等真实字段名。
- POST 示例正文 `name=Ana` 为 8 个 ASCII 字节，和 `Content-Length: 8` 一致。
- 200、304、404 是独立选择的响应状态，不随四个检查阶段变化；304 在正文阶段没有消息体，第三阶段呈现 CRLF 空行边界。GET 首部模式没有正文。
- `messageModel(mode, stage, status)` 为报文 DOM 与阶段审查提供共同数据源。`work/captures/http-semantic/report.json` 的 request 起始行、CRLF、GET fields stage3、304 stage3 四态浏览器检查均为 0 LINE_ENDS findings、0 pageErrors；GET 图卡右板只显示“GET 无正文”，304右板为“复用缓存”。200/304/404×阶段全状态矩阵由 audit-b 最新记录另行覆盖。
- 304 响应语义可参照 [RFC 9110 §15.4.5](https://www.rfc-editor.org/rfc/rfc9110.html#name-304-not-modified)。
- RTT/RTO 图中的 `EstimatedRTT + 4Dev` 明确按教材简化估计展示，不等同完整 RFC 算法；真实 SRTT/RTTVAR 更新顺序与 RTO 下限见 [RFC 6298 §2.3–2.4](https://www.rfc-editor.org/rfc/rfc6298.html#section-2.3)。TCP 建连中的 SYN/ACK 序号规则可参照 [RFC 9293 §3.5](https://www.rfc-editor.org/rfc/rfc9293.html#name-establishing-a-connection)。
